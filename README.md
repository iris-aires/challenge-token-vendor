# Token Vendor

A decentralized token vendor built with Next.js, Scaffold-ETH 2, Foundry, and Solidity. The ERC-20 token is Lumen (`LUM`), and the vendor contract supports a fixed exchange rate of 1 LUM per ETH.

## Local development

Requires Node.js 20.18.3 or later, Yarn 4, and Foundry.

```bash
yarn install
```

Run each command in a separate terminal:

```bash
yarn chain
yarn deploy
yarn start
```

Open http://localhost:3000.

## Pages

- `/`: project overview and wallet connection.
- `/token-vendor`: wallet and vendor balances, token transfers, and purchases. The sell form remains commented out until the buyback implementation is complete.
- `/events`: token purchase history.
- `/debug`: inspect and interact with contracts.
- `/blockexplorer`: local blocks, addresses, and transactions.

The interface supports dark and light themes, with the theme control next to the wallet account in the header.

## Project structure

- `packages/foundry/contracts/Lumen.sol`: Lumen ERC-20 token.
- `packages/foundry/contracts/Vendor.sol`: fixed-rate purchases, buybacks, and owner withdrawals.
- `packages/foundry/test/Vendor.t.sol`: contract tests.
- `packages/nextjs/app/`: application pages.
- `packages/nextjs/components/`: shared interface and wallet components.
- `packages/nextjs/styles/globals.css`: themes and responsive styling.

Selling tokens requires approving the vendor to spend tokens before calling `sellTokens`. Contract deployment generates `packages/nextjs/contracts/deployedContracts.ts`; do not edit this file manually.

## Testnet deployment

Configure `packages/nextjs/scaffold.config.ts` for the target network. Set up and fund a deployer wallet, then run:

```bash
yarn deploy --network sepolia
yarn verify --network sepolia
yarn vercel
```

Account and testnet deployment commands require interactive credential entry. Keep private keys and environment credentials out of version control.

## Sepolia deployment troubleshooting

Deployments wait for each transaction to succeed before submitting the next one. Sepolia uses a 1000% gas estimate multiplier because the installed Foundry simulator can underestimate contract creation gas compared with the RPC. This raises the gas limit, not the gas price; unused gas is not charged. Other networks retain the 130% multiplier.

If a previous deployment reverted onchain, run a fresh deployment rather than resuming consumed nonces:

```bash
yarn deploy --network sepolia
```

If needed, override the multiplier with `DEPLOY_GAS_MULTIPLIER=1200 yarn deploy --network sepolia`. Confirm that both contract creation receipts succeeded before using their addresses. Calls to an address without contract code may still return a successful receipt, so successful transfer or ownership transactions alone do not prove deployment succeeded.
